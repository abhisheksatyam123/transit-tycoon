# Remaining OpenTTD backlog: evidence, options, decisions (2026-11-10)

Each item: OpenTTD default (from `openttd/src/table/settings/*.ini`), what Transit Tycoon (TT) does now,
options, and a recommendation. Items marked **DONE** or **N/A** need no decision. Items marked **DECISION** need
an explicit choice before implementation, because the OpenTTD default changes gameplay or the world hash.

## Decisions needed

### 1. `vehicle.aircraft_range` (def true)
- OpenTTD base aircraft: `max_range = 0` (unlimited). The trailing `0` in the `AVI` macro (`table/engines.h`).
  Range comes only from NewGRF (`PROP_AIRCRAFT_RANGE`). So the default-on setting is a no-op for the base set.
- TT: no range field. Matches the base set.
- **Recommendation:** keep as is. No decision needed unless you want invented ranges (see `aircraft-range-gap.md`).

### 2. `vehicle.wagon_speed_limits` (def true)
- OpenTTD: a consist moves at the slowest wagon's speed when this is on.
- TT: all 30 wagon models have `speed: 0` (`js/config/vehicles.js`). Consist speed = engine speed only. No data to port from.
- Options:
  a. Keep off (TT behaviour). Document as not ported.
  b. Add per-wagon speeds (new data, values chosen by us) and cap consist speed by the slowest wagon. Default-changing: the cap applies by default in OpenTTD, which would change routes and the world hash.
  c. Add the cap as opt-in, default off (hash unchanged). Needs the same invented data as (b).
- **Recommendation:** (a) for now. Choose (c) if you want the mechanic.

### 3. Slope steepness: `vehicle.train_slope_steepness` (def 3), `vehicle.roadveh_slope_steepness` (def 7), scale 0–10
- OpenTTD: slope slows vehicles by steepness. Default 3 (train), 7 (road).
- TT: `gradients` in `js/simulation/movement.js` is the OpenLoco pitch force, not an OpenTTD steepness. No direct mapping.
- Options: (a) keep TT pitch model, not ported; (b) map the OpenTTD steepness onto the pitch force with a multiplier. Default-changing unless the default is set to "current" (which is not OpenTTD's default).
- **Recommendation:** (a). Choose (b) only with a chosen default that keeps the hash.

### 4. Timekeeping: `economy.timekeeping_units` (def Calendar), `economy.minutes_per_calendar_year` (def DEF_MINUTES_PER_YEAR)
- TT: fixed `TICKS_PER_DAY = 96` (`js/simulation/constants.js:24`), one calendar day per 96 ticks.
- Changing the clock changes every timed event and the world hash.
- Options: (a) keep, not ported; (b) expose `minutes_per_calendar_year` mapped to ticks per year, default equal to today's rate. Needs the exact equivalence. Default-preserving only if the default maps to exactly 96 ticks/day.
- **Recommendation:** (a). Requires a design call on the calendar mapping before any change.

### 5. Loading model (partly done in Round Y): `order.improved_load` (def true), `order.gradual_loading` (def true), `order.selectgoods` (def true), `station.station_length_loading_penalty`
- TT: loading is `loadSlice` in `js/simulation/orders.js` (no improved or gradual loading setting, no station-length penalty).
- Changing how cargo is shared or loaded changes money and the world hash.
- Options: (a) keep TT loading, not ported; (b) add each flag as an opt-in, default off (hash unchanged); (c) port the OpenTTD defaults, which change behaviour.
- **Recommendation:** (a) now. (b) for `selectgoods` and `improved_load` is the smallest first step, but it needs a loading design.
- **Status (Round Y): opt-in implemented.** `selectgoods` = `selectGoods` (def on, the previous behaviour: a station takes producer cargo only after a vehicle tried to load there; off = every station in range). `improved_load` = `improvedLoad` (def off; on = among vehicles loading the same cargo at a station, the earliest arrival loads first, ties by id). Limits: simplified arrival-order priority (no multi-tick cargo reservation as in `economy.cpp` ReserveConsist); mixed consists compare whole-vehicle capacity and cargo; cargodist parcels are not ranked. `gradual_loading` = `gradualLoading` (Round AA, def off): per-cycle loading and unloading with OpenTTD's per-class amounts and waits; see `docs/decisions/gradual-loading.md`. `station_length_loading_penalty` = `stationLengthLoadingPenalty` (Round Z, def off): a train longer than its platform takes the OpenTTD stop-time penalty (`platformLength.js` loadingTicksFor; about 4x for one tile of overhang). `gradual_loading` is not ported: it needs a per-model load amount (OpenTTD `load_amount` per engine, not in TT data) and a multi-step loading loop (TT loads everything at the end of the stop), so it is a design decision, not a flag.

### 6. Road acceleration: `vehicle.roadveh_acceleration_model` (def Realistic)
- TT: road vehicles move at `maxSpeed` with bridge and curve limits only (`js/simulation/movement.js`). No acceleration model. `trainAcceleration` (original/realistic) exists for trains only.
- OpenTTD default Realistic would change road timing and the world hash.
- **Recommendation:** keep TT road movement. Opt-in acceleration needs a design.

### 7. Town cargo generation: `economy.town_cargogen_mode` (def Bitcount)
- OpenTTD: `Original` = quadratic per-tick generation; `Bitcount` = binomial per tick at a quarter rate (`town_cmd.cpp:626-640`).
- TT: its own model (`js/simulation/cargo.js` `distributeTownCargo`, `loco/town.js`). Not OpenTTD's generation.
- **Recommendation:** keep TT's model. Porting either mode changes passenger and mail volume and the world hash.
